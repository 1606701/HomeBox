# HomeBox v2 产品需求文档（PRD）

| 项 | 内容 |
| --- | --- |
| 版本 | v2.0（简单 PRD，不含竞品分析） |
| 语言 | 中文 |
| 项目名 | homebox |
| 形态前提 | 沿用 v1：低功耗 ARM（树莓派 / 香橙派，内存 1–4GB，TF 卡系统盘）、局域网自托管、手机为主 PWA |
| 原始需求 | ①数据层改造以支持历史流水 ②定时任务（过期 / 低库存 / 闲置）+ 邮件推送 ③用户鉴权以承载「物品价值」 ④拍照识别辅助分类与录入 |
| 迁移底线 | 现有 19 个位置 / 26 件物品（含 14 件衣物、1 张照片、户型宽度 12m）**零重录**升级 |

## 1 产品定位

**一句话定位**：HomeBox v2 是放在家里、不出家门的「家庭物品管家」——先回答「东西在哪」，再回答「还够不够、过没过期、值多少钱、是谁的」。

| 维度 | v1（已实现） | v2（本 PRD） |
| --- | --- | --- |
| 核心问题 | 东西在哪 | 东西在哪 + 状态/存量/价值/归属 |
| 数据来源 | 用户手动录入 | 手动录入 + 识别辅助 + 自动累积的时间流水 |
| 主动能力 | 无（纯被动查询） | 到期/补货主动提醒（站内 + 邮件） |
| 使用者 | 1 人 | 单家庭 2–4 人，含老人档位 |
| 金钱视角 | 无 | 购入金额汇总，仅存储不涉及支付 |

**明确不做（v2 边界）**：
1. 不做公网访问、不做云同步、不做任何家庭数据出家门（拍照识别除外，见 Q2，需显式授权）。
2. 不做多家庭 / 多租户 / 合租场景；一个部署 = 一个家庭。
3. 不做记账（收支流水、预算、报表导出为财务格式）——只做「已购物品金额汇总」。
4. 不做电商比价、自动下单、补货履约。
5. 不做扫码商品库匹配、不做多图相册、不做视频；每件物品仍只保留 1 张主图。
6. 不做物品出借的社交/共享/二手交易；「借出对象」只记一个名字。

## 3 信息架构

**结论：v2 采用 5 个一级入口**（v1 的 4 个 + 新增「提醒」）。价值统计与成员管理**不占一级**，收为二级。

| 一级入口 | 职责 | 二级入口 |
| --- | --- | --- |
| 找东西（默认首页） | 搜索、结果卡片、顶部统计条 | 家的概览（价值统计）、物品详情、成员、设置 |
| 地图 | 户型 SVG、内部视图、真实面积 | 房间/家具详情 |
| 衣柜 | 四维筛选、今日穿什么 | 衣物详情 |
| 提醒（新增） | 全部待办的单一下沉地：过期、待补货、借出未还、未归位、闲置（可选） | 通知设置、订阅管理 |
| 记一件 | 录入 | 识别结果确认 |

**决策理由**：
1. 手机底部导航最多 5 个图标仍能保证拇指命中区与 ≥44px 点击高度，超过 5 个就要缩字号，与「老人也要能用」冲突。
2. 价值统计是**低频**动作（月度/年度看一次），不配一级入口；它天然承接现有「找东西」页顶部统计条——把已有位置从展示变成入口，不新增认知成本。
3. 成员管理是**一次性**动作（装机时加 3 个人），藏进「找东西 → 右上角家」即可。
4. 「提醒」必须是一级：它是 v2 唯一会主动找用户的东西，红点必须常驻可见；若收进二级，邮件与站内会脱节。

## 4 核心流程

**a) 带拍照识别的录入（主路径 ≤5 步）**
1. 点「记一件」→ 首屏只有三件东西：**拍照/选图按钮（大）**、名称输入框、位置选择器（默认记住上次位置）。
2. 拍照 → 上传识别 → 返回候选：名称、类目（受控 8 类）、建议标签、建议保质天数、建议位置（基于该类目历史位置）。
3. 用户逐项「采纳 / 改」，识别结果**永远是草稿**，必须点「保存」才写库。
4. 命中「食品 / 药品 / 日化」类目时，自动展开「过期日」一行（其余高级字段仍折叠）。
5. 异常分支：
   - 识别超时/无网/未开授权 → 顶部一行灰字「识别暂不可用，先手动记」，**表单照常可用**，不弹窗、不阻断。
   - 识别错 → 每个字段右侧「改」；名称可直接编辑；提供「结果不对」轻量反馈（只本地记录，用于后续收紧提示词）。
   - 照片过大/格式不支持 → 沿用 v1 的压缩与报错文案，提示重新拍或从相册选压缩版。

**b) 过期与补货提醒的触达路径**
1. 服务每天固定时间离线算一次（不是实时推理）→ 生成「今日待办」。
2. 站内：底部「提醒」出红点，数字 = 未处理条数；点开是分组清单（今天过期 / 3 天内 / 已过期 / 待补货 / 借出未还）。
3. 邮件：每天早间一封**汇总**（不是每条一封），正文按组列出，附直达链接。
4. 卡片三动作：**已处理**（用完/已扔/已买）、**稍后 7 天**、**不再提醒这件**。做过「已处理」的当天不再出现在任何通知里。
5. 存量补充：点「已买」→ 直接进入「记一件」并预填该物品名称、位置、类目。

**c) 金额统计的查看路径**
1. 找东西页顶部统计条 → 点「¥ 合计」→「家的概览」。
2. 概览三页签：**按位置 / 按类目 / 按成员**；时间范围：全部 / 今年 / 近 3 个月。
3. 每块条形下方固定一行「已记录 12 件 · 未记录 14 件」，未填价的不计 0，避免「总价值 ¥0」误读。
4. 点任一柱 → 物品列表（带价格与购入日期），可原地补价。
5. 概览底部单列「累计购入（含已用完/已丢弃）」与「当前在库价值」两个数，口径不混。

**d) 成员与归属**
1. 升级后首次打开 → 引导创建「家庭管理员」（名字 + 密码，1 次）。
2. 管理员在「成员」页添加家人：只填名字 + 选档位（管理员 / 成员 / 精简 / 访客），**不要求填邮箱、不要求每人注册**。
3. 日常登录：同一局域网内设备记住上次身份，7 天免登录；切换人 = 点左上角头像选名字。
4. 归属：新录入默认归属当前登录人，可改「共用」；旧数据归属为空显示「未指定」，筛选里单独一组。

## 5 字段设计（产品视角）

| 字段 | 为什么需要 | 谁填 | 必填 | 默认 | 对现有 26 件旧数据的影响 |
| --- | --- | --- | --- | --- | --- |
| `category` 类目（受控 8 类：食品/药品/日化清洁/耗材配件/工具/电子/衣物/其他） | 统计维度、默认保质期、识别输出都靠它；自由 tag 无法聚合 | 用户点选 / 识别预填 | 否 | 空 | 旧数据显示「未分类」，统计里单列一档；14 件衣物按 wear.type 自动归「衣物」，不需重录 |
| `expireAt` 过期日 | 过期提醒的唯一依据 | 用户 | 否 | 空 | **空值一律不进任何提醒**，只在「补全信息」软提示里出现，避免升级即被轰炸 |
| `remindDays` 提前提醒天数 | 不同品类提前量不同（牛奶 3 天、药 30 天） | 系统按类目给默认，用户可改 | 否 | 食品/日化 3 天，药品 30 天 | 不适用（旧数据无过期日） |
| `minQty` 最低库存 | 补货提醒的阈值；不填就不提醒 | 用户（仅耗材类才展开） | 否 | 空（=不提醒） | 旧数据为空 → 不触发；「5 号电池」等耗材需用户手动补一次阈值 |
| `qty` 数量 | v1 已有，v2 参与低库存判断 | 用户 | 是 | 1 | 沿用，不改语义 |
| `price` 购入单价 | 金额统计的原子数据 | 用户（折叠区） | 否 | 空 | 空值不计入金额，但计入「未记录」覆盖率；老用户会看到新字段，属预期 |
| `buyDate` 购入日期 | 区分「今年花了多少」；不填则时间维度缺失 | 用户 | 否 | 空（**不默认今天**，避免把补录数据算进今年支出） | 旧数据为空 → 时间筛选里归「日期未知」 |
| `currency` 货币 | 家庭可能有外币购入 | 家庭设置一次性设 | 否 | 跟随家庭设置（默认 CNY） | 不适用 |
| `ownerId` 归属人 | 家庭多人场景的「谁的」、按人统计 | 默认当前登录人 | 否 | 当前登录人；可选「共用」 | 旧数据为空 → 显示「未指定」，所有档位都可见，不做权限拦截 |
| `state` 状态（在用 / 用完了 / 已借出 / 已丢弃） | 区分「存量 0」与「已不在家」；支撑累计购入 vs 在库价值 | 用户一键 | 否 | 在用 | 旧数据为空视为「在用」；**与衣物 wash 状态正交，不冲突**（待洗是循环态，不是终态） |
| `lendTo` / `lendAt` 借出对象与日期 | 「借出去的东西」是家庭高频痛点 | 用户 | 否 | 空 | 不适用 |
| 变更留痕（新增/改量/移库/借出/归还/丢弃） | 金额与「上次什么时候买的」的解释链；也是 v2 数据层改造的产品诉求 | 系统自动 | 是 | 自动 | 旧数据补一条「v1 迁移导入」的初始记录，不伪造历史 |

## 7 通知策略（家庭场景，不做骚扰）

| 规则 | 取值 |
| --- | --- |
| 合并 | 一天最多 1 封汇总邮件；站内红点常驻，不弹窗、不推送系统通知 |
| 发送时间 | 默认 08:00（家庭设置可改），**21:00–08:00 一律不发**，跨夜事项顺延至次日 |
| 频率上限 | 同一件物品同一类型提醒 **7 天内只发 1 次**；已过期物品只在当天与过期后第 1 天各发 1 次，之后每 7 天收敛 1 次 |
| 单封容量 | 最多 10 条，超出只写「还有 N 条」并给直达链接 |
| 沉默期 | 连续 3 天无人打开 App（家里没人/出差）→ 暂停邮件，恢复活动后合并成 1 封 |
| 订阅粒度 | 4 类独立开关：过期提醒 / 补货提醒 / 借出未还 / 家庭周报。闲置提醒默认关 |
| 退订 | 每封邮件底部一键退订该类别，立即生效（下一封即停）；也可在「提醒 → 订阅管理」改 |
| 不做 | 不做每条一封、不做短信、不做系统级推送轰炸、不做「猜你喜欢」类营销内容 |

## 8 待确认问题（需用户拍板）

| # | 问题 | 我的推荐 |
| --- | --- | --- |
| Q1 | 是否需要「老人精简档」这种降权账号？ | **需要**。这是「家里 2–4 人且可能有老人」的直接结论，也是最省事的做法（不给金额、不给删除） |
| Q2 | 拍照识别需要把照片发给外部识别服务，与「数据不出家门」冲突，接受吗？ | **接受，但默认关闭**；首次开启显式确认，并在设置里写明「照片会离开本机」；关闭后功能可完全手填 |
| Q3 | 金额统计口径：只算现存物品，还是含已用完/已丢弃？ | **两个数都显示**：「当前在库价值」与「累计购入」，默认选中在库 |
| Q4 | 登录方式：家庭账号密码，还是局域网内点人头？ | **管理员设密码，成员点人头**（7 天免登录）。局域网信任 + 老人门槛优先 |
| Q5 | 闲置提醒是否默认开启？ | **默认关闭**，只在站内提醒页展示；家庭场景下「这瓶酱油一年没动」的邮件极易变成噪音 |
| Q6 | 邮件发件邮箱由家里自备（自己申请一个邮箱填配置），可以吗？ | **可以**。产品只提供填写入口与「发测试邮件」按钮，不自建邮件服务 |

## 9 v1 功能保留 / 调整 / 砍

**一分不动（回归即视为 Bug）**
1. 搜索机制：name / note / tags / 路径的子串匹配 + 按更新时间倒序（这是核心卖点，不许改排序逻辑）。
2. 地图：SVG 户型拖拽、改尺寸、改名、改归属、删位置（物品降级未归档）、内部视图抽屉、家具四档热力、按户型宽度换算真实面积。
3. 衣柜：四维 AND 筛选、「今日穿什么」按季节择少穿、记录今天穿了 +1 并转待洗（含撤销）。
4. 照片：前端压缩上传、换图删旧图、大图查看。
5. PWA + 离线可用、toast、标签分布与每房间分布条形图、统计条三项基础数字。

**要改交互**
1. 「记一件」表单：字段分组折叠，位置选择器记住上次；类目命中食品/药品/日化时自动展开过期日。
2. 物品卡片：只加 3 个小角标（金额、归属人、过期），不再加更多；已丢弃/已借出用灰度区分。
3. 统计条：从 3 项扩到 4 项（件数 / 位置数 / 未归位 / 合计金额），整条可点进「家的概览」。
4. 地图页：房间详情里增加「该房间已记录金额」一行（只读，不改地图交互）。
5. 衣柜：筛选栏新增「归属人」（P1），其余不动。

**可以砍 / 降级**
1. 地图页的「树形列表模式」与「找东西」页列表重复 → 降级为地图页二级切换（保留功能，不再占首屏）。
2. 首次启动写入示例数据 → v2 **不再写入**（用户已有真实数据，示例数据会变成污染）。
3. 照片单图限制、无多图相册：明确不做，不进入任何排期。
